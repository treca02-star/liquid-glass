# Режим «существующий сайт на React»

Для сайта, который уже написан на React (Vite, Next, CRA и другие) и у которого нужно поменять вид, а не устройство. Набор из `assets/kit/` рассчитан на простые HTML-страницы; сюда из него переносится вид, а поведение берётся из `assets/react/glass.tsx`.

## Главное правило

Меняется только внешний вид. Логика, адреса страниц, запросы к серверу, проверка прав, заголовки защиты и способ хранения данных остаются как были. Если ради вида приходится трогать что-то из этого списка, остановись и спроси пользователя.

## Что берём и что нет

| Из набора | В React |
|---|---|
| `tokens.css`, `base.css`, `glass.css` | берём как есть, подключаем один раз в корне приложения |
| `glass.js` | **не подключаем**: он пишет в `localStorage` и сам вставляет разметку |
| `starter.html`, страницы-примеры | не копируем; из них смотрим разметку и переводим в JSX (`class` становится `className`) |
| поведение (меню разделов, шторка, меню из кнопки, уведомления) | `assets/react/glass.tsx` |
| `design.md` | кладём в корень проекта, если там ещё нет своего |

Если в проекте уже есть свои токены или Tailwind, не заводи вторую систему: перенеси значения из `tokens.css` в существующую и сохрани имена проекта. Если в проекте свой сброс стилей, `base.css` сверь с ним, а не подключай поверх вслепую.

## Порядок

1. **Прочитай проект**: сборщик, роутер, где лежат стили, есть ли TypeScript, какая политика CSP (заголовок или мета-тег), где хранится состояние. Назови пользователю файлы, которые будешь менять.
2. **Подключи вид**: три CSS-файла в корне приложения. Шрифт Onest подключай так, как разрешает проект. При строгой CSP ссылка на Google Fonts не пройдёт: положи шрифт в проект или оставь шрифт проекта и впиши его в `--font-body` и `--font-display`.
3. **Скопируй `glass.tsx`** в папку компонентов проекта. В проекте без TypeScript убери из файла типы и сохрани как `.jsx`.
4. **Оберни приложение** в `<GlassProvider>`. Он добавляет класс `js` на `<html>` (без него часть стекла отображается неверно) и даёт уведомления.
5. **Переводи экраны по одному**: каркас (`.bar`, `main.app`, `GlassDock`), потом модули. Правила деления на страницы и модули те же, из `layout.md`. После каждого экрана проверяй, что его действия работают как раньше.
6. **Проверь** по `hallmark.md`. Линтер читает `.jsx` и `.tsx`; для собранного приложения запускай его с `--url http://localhost:<порт>/<путь>` при работающем сервере разработки. Hallmark сам не берётся за существующий дизайн без команды `/hallmark redesign`, поэтому здесь он только проверяет. Проверяй папку, где компоненты лежат вместе с тремя CSS-файлами: если дать линтеру один `glass.tsx` без стилей, он ложно сообщит `26a` (нет стиля фокуса), потому что стили состояний живут в `glass.css`.

## Компоненты из `glass.tsx`

```tsx
import { GlassProvider, GlassDock, GlassMenu, Sheet, Icon, useToast, usePageTitleSwap } from './glass';

// Меню разделов. Ссылки роутера передаются через renderLink, адреса не меняются
<GlassDock
  items={[{ href: '/', label: 'Обзор', icon: 'home', current: pathname === '/' }, …]}
  renderLink={(item, props, children) => <Link to={item.href} {...props}>{children}</Link>}
  status={running && <span className="dock-status glass"><Icon name="timer" />{left}</span>}
/>

// Шторка: открытие хранится в состоянии компонента
<Sheet open={open} onClose={() => setOpen(false)} title="Новая запись"
       footer={<button type="submit" form="f" className="btn btn--block">Сохранить</button>}>…</Sheet>

// Меню из кнопки; пункты это кнопки с классом menu__item
<GlassMenu buttonLabel="Ещё действия" title="Действия">
  <button type="button" className="menu__item" onClick={exportData}><Icon name="download" />Экспорт</button>
</GlassMenu>

// Уведомление, в том числе с отменой
const toast = useToast();
toast('Удалено', { label: 'Вернуть', run: restore });

// Название страницы в шапке при прокрутке
const title = useRef<HTMLHeadingElement>(null);
usePageTitleSwap(title);   // <h1 className="page-title" ref={title}>
```

Остальные детали (модуль, плитки, кнопки, поля, таблетки, переключатель, таблица, состояния) это просто разметка с классами из `components.md`, отдельные компоненты им не нужны.

## Строгая защита (CSP) и хранение

- `glass.tsx` не использует `localStorage`, `sessionStorage` и cookie. Не добавляй их ради вида: настройки вида задаются в `tokens.css`, а не хранятся у пользователя.
- В JSX не пиши `style={{…}}` и не вставляй теги `<style>`. Размеры и положение, которые считаются на лету, передавай через `element.style.setProperty` в эффекте: так делает `glass.tsx`, и это проходит `style-src 'self'`.
- Преломление стекла (`data-lens`) в React-версию не перенесено: ему нужны картинки `data:` в `img-src`. Стекло остаётся с размытием. Не ослабляй CSP ради эффекта.
- Не добавляй внешние скрипты и шрифты с чужих адресов, если политика их не разрешает.
- Иконки встроены в `glass.tsx` как JSX; новую иконку добавляй в объект `ICONS` там же.

## Чего не делать

- Не переписывай роутинг на отдельные HTML-страницы: «раздел это страница» здесь означает отдельный маршрут роутера.
- Не меняй названия полей форм, адреса запросов и формат данных.
- Не убирай существующие состояния загрузки и ошибок: переодень их в `.skeleton`, `.empty`, `.state-error`.
- Не сдавай без проверки, что вход, выход и главные действия работают как до переделки.
